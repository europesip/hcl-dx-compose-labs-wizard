Configuration wizard

Answer a few questions and download your env.sh (and, if you want, a personalised RUNBOOK.md) for the hcl-dx-compose-labs.

⚠ Experimental (work in progress) and optional: the recommended path is the manual one. 🔒 Runs entirely in your browser: nothing is sent. About this wizard, source code and privacy →

1 · Platform

Where will DX Compose run? Every field is pre-filled with the values of the reference lab environment; only the Harbor and OpenRouter credentials are empty.

Lab 0 is a simplified, "tweaked" PoC environment (simulated RWX StorageClass, reduced resource requests). Not valid for production.

2 · Access to DX

It must resolve to your Ingress controller or OpenShift router. Without DNS, a nip.io name such as dx.192.168.1.50.nip.io works.

Corporate TLS certificate (optional)

By default Lab 1 generates a self-signed certificate. To use yours, give the paths on your workstation.

3 · Storage

DX needs one ReadWriteOnce and one ReadWriteMany StorageClass. Your cluster administrator provides them.

4 · Labs

Lab 1 is always included. Labs 3 and 4 only need Lab 1.

5 · Credentials (optional)

Leave any field empty and fill it in later in env.sh. Values typed here stay in this page and in the files you download.

Pre-filled with the public lab default EuropeS1P (the one used in the labs); empty = the same default. Avoid the characters ' " \ $ & |.

Active Directory

Oracle

6 · Advanced

Namespaces, Helm releases, PostgreSQL cluster and Helm version (defaults are fine)

Kubernetes names: lower case letters, digits and hyphens. Keep the search release as dx-search unless you know why (the DX chart expects it for the shared push-admin credential).

7 · Your files

Choose what you need:

Option A · Only env.sh

Just the configuration file the labs need. Then follow the labs manually, with the guide of each lab (GUIDE.md / GUIDE.es.md).

Option B · env.sh + RUNBOOK.md

A ZIP with env.sh and RUNBOOK.md: the instructions to build, one after the other, the labs you selected, with the scripts to run and the equivalent commands using your values.

Option C · Direct installation (runbook/)

A ZIP that creates a runbook/ folder: a RUNBOOK.md with direct commands (your values written in each command, checks marked as optional), an install.sh that runs it all showing the lab and step, secrets.env and the generated values files. It overwrites nothing.

A and B: put the files in the root of your clone of the repository (next to env.example.sh) and source ./env.sh; the lab scripts install everything. C: unzip it in the root of the clone (it creates runbook/), fill in runbook/secrets.env, then cd runbook and follow its RUNBOOK.md or run ./install.sh. env.sh and runbook/ are in .gitignore.
