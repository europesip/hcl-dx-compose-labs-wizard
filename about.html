Configuration wizard for the DX Compose labs

An optional helper for the hcl-dx-compose-labs (HCL DX Compose CF238 installed from scratch on Kubernetes, as a PoC). Read this page once; then choose below whether you want to use the wizard or follow the labs manually.

Experimental · work in progress. The wizard is evolving constantly and must be treated as experimental. It aims to make the installation easier and clearer, but the recommended path today is the one without the wizard: cp env.example.sh env.sh, edit it and follow the guide of each lab. Both ways give the same result.

What you get: the three options

The wizard asks for your platform (Kubernetes, OpenShift or the WSL2 PoC), the DX host name, the StorageClasses, namespaces and release names and the labs you want. Every field comes pre-filled with the values of the reference lab environment; only the Harbor and OpenRouter credentials are empty. At the end you choose one of three options:

In all three the installed result is the same, and the wizard only generates files: it never talks to your cluster.

Your credentials stay yours: check it yourself

Private by design. Everything runs in your browser: nothing you type is sent anywhere and there are no analytics or external scripts. Secrets (Harbor token, OpenRouter key, passwords) are optional: leave them empty and fill them in later in env.sh, which is in .gitignore and is never committed.

So that anyone can verify it, the wizard was built as one single file, index.html, with plain HTML, CSS and JavaScript: no React, no frameworks, no build step and no dependencies. What you read is exactly what runs, it is easy to review, and it works on GitHub Pages as is.

  • Source code: its own repository, github.com/europesip/hcl-dx-compose-labs-wizard, and the published copy in the labs repository (docs/).
  • Use it online on GitHub Pages, without installing anything: europesip.github.io/hcl-dx-compose-labs.
  • Or run it locally: download index.html and open it in your browser. It works offline.
  • No network, enforced by the browser: both pages declare a Content-Security-Policy with connect-src 'none', so the browser blocks any request even if the code tried to send something.
  • The only thing stored in your browser is the language you choose (localStorage).

How to check it:

  1. Read index.html (the JavaScript is at the end, after the LAB TEMPLATES block).
  2. Search it: there is no fetch, XMLHttpRequest, WebSocket, sendBeacon or external script or style. 
    sed '/BEGIN LAB TEMPLATES/,/END LAB TEMPLATES/d' index.html | grep -nE 'fetch\(|XMLHttpRequest|WebSocket|sendBeacon|<script src|<link '
    The LAB TEMPLATES block is excluded because it is not code: it holds text copies of the lab files that option C fills in and puts in the ZIP (one of them, iq-chat.py, talks about WebSocket). The page never runs them.
  3. Open your browser developer tools, Network tab, fill in the form and download: there are no requests.
  4. Or run it locally with the network disconnected.

Asistente de configuración de los labs de DX Compose

Una ayuda opcional para los hcl-dx-compose-labs (HCL DX Compose CF238 instalado desde cero en Kubernetes, a modo de PoC). Lee esta página una vez; después elige, abajo, si quieres usar el asistente o seguir los labs a mano.

Experimental · en desarrollo (WIP). El asistente evoluciona constantemente y debe tratarse como algo experimental. Busca facilitar y aclarar la instalación, pero hoy la vía recomendada es la que no usa el asistente: cp env.example.sh env.sh, editarlo y seguir la guía de cada lab. Las dos formas dan el mismo resultado.

Qué obtienes: las tres opciones

El asistente pregunta tu plataforma (Kubernetes, OpenShift o la PoC en WSL2), el nombre de host de DX, las StorageClasses, los namespaces y nombres de releases y los labs que quieres hacer. Todos los campos vienen rellenos con los valores del entorno de referencia de los labs; solo las credenciales de Harbor y OpenRouter están vacías. Al final eliges una de estas tres opciones:

Tus credenciales siguen siendo tuyas: compruébalo tú mismo

Privado por diseño. Todo funciona en tu navegador: nada de lo que escribes se envía a ningún sitio y no hay analítica ni scripts externos. Los secretos (token de Harbor, clave de OpenRouter, contraseñas) son opcionales: déjalos vacíos y rellénalos después en env.sh, que está en .gitignore y nunca se sube a git.

Para que cualquiera pueda comprobarlo, el asistente se ha construido como un único fichero, index.html, con HTML, CSS y JavaScript sencillos: sin React, sin frameworks, sin compilación y sin dependencias. Lo que lees es exactamente lo que se ejecuta, es fácil de revisar y funciona tal cual en GitHub Pages.

  • Código fuente: su propio repositorio, github.com/europesip/hcl-dx-compose-labs-wizard, y la copia publicada en el repositorio de los labs (docs/).
  • Úsalo en línea en GitHub Pages, sin instalar nada: europesip.github.io/hcl-dx-compose-labs.
  • O ejecútalo en local: descarga index.html y ábrelo en tu navegador. Funciona sin conexión.
  • Sin red, garantizado por el navegador: las dos páginas declaran una Content-Security-Policy con connect-src 'none', así que el navegador bloquea cualquier petición aunque el código intentara enviar algo.
  • Lo único que se guarda en tu navegador es el idioma elegido (localStorage).

Cómo comprobarlo:

  1. Lee index.html (el JavaScript está al final, tras el bloque LAB TEMPLATES).
  2. Búscalo: no hay fetch, XMLHttpRequest, WebSocket, sendBeacon ni scripts o estilos externos. 
    sed '/BEGIN LAB TEMPLATES/,/END LAB TEMPLATES/d' index.html | grep -nE 'fetch\(|XMLHttpRequest|WebSocket|sendBeacon|<script src|<link '
    Se excluye el bloque LAB TEMPLATES porque no es código: contiene copias en texto de los ficheros de los labs que la opción C rellena y mete en el ZIP (uno de ellos, iq-chat.py, habla de WebSocket). La página nunca los ejecuta.
  3. Abre las herramientas de desarrollo del navegador, pestaña Red (Network), rellena el formulario y descarga: no hay peticiones.
  4. O ejecútalo en local con la red desconectada.
